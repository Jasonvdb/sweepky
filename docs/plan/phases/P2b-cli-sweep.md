# P2b — `sweepky-cli`: post, run and submit

## Goal

`post` for closed bounties, `run` and `submit`, so a circle member can sweep a closed bounty end to end on the testnet. It builds on [P2a](P2a-cli-identity.md) for the network config, the `--identity` login, the circle, the writers' lock, the config directories, the minimal `init` with its marker, and the testnet test; on [P1a](P1a-core-records.md) for targets, the Cloudflare converter and the bare fixture repo; and on [P1b](P1b-core-crypto.md) for the package envelope, padding and encryption. `post --open`, `pull` and `done` follow in [P2c](P2c-cli-pull-done.md).

## Build

- **`post` (without `--open`):** pins SHAs through a `TargetResolver` trait: the real one runs `git -c credential.helper= -c core.askPass= ls-remote` with `GIT_TERMINAL_PROMPT=0` (peeling annotated tags, storing full SHAs) and GitHub's unauthenticated REST API for PR head, base and merge base; the fixture one serves a bare repo under `fixtures/`. Refuses repos that are not anonymously readable. `title` and `brief` are shown for confirmation.
- **`run [<bounty-url>] [--target <tid>]`:** must be run inside an `init` project; picks or checks the bounty (circle or `open`); writes `running`; fetches each target into `./sweeps/<id>/target/<tid>/` by exact SHA (https only, depth 2, no submodules, no LFS, credential helpers disabled; PR heads from the base repo's `refs/pull/<n>/head`); removes `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.claude/` and `.mcp.json` from the copy and lists them in `scope.json`; writes `scope.json`, the brief and `.sweepky/sweep.json` (sweep URL, bounty URL, target ids, playbook id from `init`); aborts if the SHA is not served.
- **`submit [--run-dir] [--playbook]`:** canonicalise; require a direct child of `<init dir>/sweeps/` with the marker; walk with `symlink_metadata`, accept regular files with one link only, skip `agents/*/scratch/` and `target/`, cap per-file and total size, print the list; detect Cloudflare output in `audit/` and convert; read the bounty, list the owner's unrevoked `keys/`, compare with the pinned set and warn on new keys (ask, or fail with `--no-input`); refuse an owner with no keys; pad, encrypt to those plus this install's key, upload `.age`, flip to `done` (or `aborted` on failure), handling 413, 429 and 507 with clear messages.

## Done when

- The testnet test from [P2a](P2a-cli-identity.md) continues, with targets from the fixture repo: A, the owner, creates a circle with B in it and posts a closed bounty; B, a circle member, runs it inside a minimal `init` project and submits a Cloudflare-format sweep.
- `submit` refuses a run directory holding a planted symlink and a hard link to `~/.config/sweepky/*`, as in [06](../06-verification-and-limits.md#verification).
- B's first `submit` pins A's key set, and a key the test then adds under A's `keys/` makes B's next `submit` warn.
- Two `submit`s by B, of two separate runs, run concurrently and both succeed, each taking the writers' lock in turn.
- `cargo clippy -- -D warnings`, `cargo deny check` and `cargo nextest run` clean.

## Notes

- The per-sweep marker `sweeps/<id>/.sweepky/sweep.json` that `run` writes is separate from the project's `.sweepky` marker that the minimal `init` writes.
- Until [P3](P3-skill-and-sandbox.md)'s `init` records a playbook, the playbook comes from `submit --playbook`.
- `RepoName` ([P1a](P1a-core-records.md)) now refuses a host whose last label starts with a digit, not only one that is all digits: a URL parser or the system resolver reads the hex and mixed IPv4 forms (`127.0x1`, `0x7f.0x0.0x0.0x1`, `10.0.0.0xa`) as an address, every such form ends in a label that starts with a digit, and no top-level domain does. It is still a check of form: a DNS name that resolves to a private address passes it.
- The question plumbing, P2b's record (`prompt.rs`, `clock.rs`). `Context` gains `cwd`, the working directory, which `main.rs` reads with `std::env::current_dir()` so that only `main.rs` reads the environment, the working directory included (a working directory that has gone fails every command but `init` before anything is done); and `stdin`, a `StdinReader` around a `Mutex<Box<dyn BufRead + Send>>`, which `main.rs` builds around `BufReader::new(std::io::stdin())`, because `Stdin` is not `BufRead` and `StdinLock` is not `Send`, and the tests around a `Cursor`. The global `--no-input` stays on `Cli` and is not in the context: `run` hands it, as a `prompt::Prompting` (`Allowed` or `Forbidden`), to each command that asks, so a test gives it on the command line like any other flag. `prompt::confirm(ctx, prompting, question)` writes `<question> [y/N] ` to `ctx.stderr` with no newline and reads one line from `ctx.stdin` with `take(1025).read_until(b'\n', …)`, never an unbounded `read_line`: a line of more than `MAX_ANSWER_BYTES` (1 KiB, its ending included) is an error that quotes none of it, and nothing past its 1025th byte is read. `y` or `yes` in any ASCII case, once one `\n` or `\r\n` is taken off, is yes; anything else, an empty line and the end of the input included, is no. Under `Forbidden` it fails at once, with an error that names `--no-input` and the question, and writes and reads nothing. The caller sanitises any stranger's text it puts in a question. `clock::new_record_id()` is the id of a new bounty, sweep or device key: it asks `clock::now()` first, which refuses a clock before 1970 that `Timestamp::now()` would panic on, then returns `RecordId::from_timestamp(Timestamp::now())`; `device::new_device_id` is that id parsed as a `DeviceId`. Until `post` and `submit` call `confirm`, `prompt.rs` carries `#![cfg_attr(not(test), expect(dead_code, …))]`; the first caller removes it, because an unmet `expect` is a warning of its own.
- The git runner, P2b's record (`git.rs`). `post` and `run` run git only through `GitRunner`, behind a small `RunGit` trait of one `async fn run(&GitCommand) -> stdout`, used generically like `device::PublicKeys` so a test can record or fake invocations. Arguments go as an argv vector, never through a shell: options are `&'static str`s the code writes, and `git_argv` refuses an operand (URL, SHA, ref or pattern) that is empty or starts with `-`. Every run gets, before its subcommand, `-c credential.helper=` (an empty value resets the helper list, Apple git's bundled `osxkeychain` included), `core.askPass=`, `protocol.allow=never`, `protocol.https.allow=always`, `http.followRedirects=false`, `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `core.symlinks=false`, `submodule.recurse=false`, `fetch.recurseSubmodules=false`, `transfer.fsckObjects=true` and `advice.detachedHead=false`; `protocol.file.allow=always` is added only for the fixture source (`AllowedProtocols::HttpsAndFile`). The child's environment is cleared, then given exactly `PATH`, whichever of `HTTPS_PROXY`, `https_proxy`, `ALL_PROXY`, `all_proxy`, `NO_PROXY`, `no_proxy`, `SSL_CERT_FILE` and `SSL_CERT_DIR` were set (`main.rs` captures them into `Context::git_env`, a `GitEnv`, and does not read `TMPDIR`), `HOME`, `GIT_CEILING_DIRECTORIES`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_LFS_SKIP_SMUDGE=1` and `LC_ALL=C`; standard input is `/dev/null`. `HOME` is `<data dir>/git-home-<new record id>/`, made 0700 through `private_fs` and refused if anything, a symlink included, is already there; a drop guard removes it with `remove_dir_all` (best effort; a process killed outright leaves it behind). `GIT_CEILING_DIRECTORIES` is the data directory: git runs in that private `HOME` by default, and without it git's search for a repository walks up from there, so a home directory kept in git (`~/.git`) would lend its `.git/config` (an `http.extraHeader`, a `url.<base>.insteadOf`) to every `ls-remote`; a data directory whose path holds a `:` is refused, because that list is `:`-separated. That variable is the one addition to the allowlist the task named; a command run in another directory (`GitCommand::in_dir`) must run in a repository it made, so the search stops there, or, for the fixture source's `merge-base`, in the fixture's bare repository, which git finds at that directory itself and so searches nothing above. Each run is bounded: standard output and standard error are read at the same time, each up to its own cap, under a timeout, and a child past any of them is killed and waited for (`kill_on_drop` as well). `ls-remote` gets 60 s, 1024 lines of at most 1024 bytes (so 1,049,600 bytes of standard output) and 64 KiB of standard error; `run`'s fetch gets 10 minutes. Killing git does not kill a helper it started (`git-remote-https`), which dies when its pipes close. A failed run is a `GitFailed` error: `git <subcommand> failed with exit status <n>`, fixed text, never git's standard error, which carries `remote:` text a server wrote; the error keeps that text only for `stderr_mentions`, a match against a fixed phrase, and its `Debug` prints its length. The `ls-remote` parser takes `<40 lower-hex>\t<ref>` lines (`HEAD` or under `refs/`, no control character, `^{}` lines included): SHA-1 only, so a SHA-256 repository is refused although core's `GitSha` also takes 64 hex characters. Minimum git: 2.32, for `GIT_CONFIG_GLOBAL` (an older git still finds no `~/.gitconfig` in the empty `HOME`). tokio's `process` and `io-util` features are named in the CLI's `Cargo.toml`; pubky already turns them on (it asks for tokio's `full` on every target but wasm), so they add no code.
- The host policy, P2b's record (`targets/host.rs`, a P1a carry-forward). v1 sweeps public repositories only, so a target's host is resolved and checked before any git contact, for every bounty, open or closed, and on both the `post` and the `run` path. `HttpsRemote::for_repo(repo, resolver)` is the only way to make the `https://<repo>` remote of a real target: through `host::check_host`, which GitHub's API host goes through too, it looks up the `RepoName`'s host and refuses, in fixed text that names neither the host nor an address, a failed lookup, an answer with no address, and an answer with any address that is not public, whatever the others are, since git connects to whichever it likes. git's network commands take only a `git::Remote`, which is an `HttpsRemote` or the fixture source's `LocalRemote` (its constructor is private to `targets/fixture.rs`; the tests of other modules have a `cfg(test)` one); every other command is built from a `LocalSubcommand` (`init`, `config`, `rev-parse` and `merge-base` so far, a variant added as a command needs one), which never contacts a repository, so no URL a record or a server wrote reaches git unchecked. The lookup goes through `ResolveHost`, a trait of one async fn used generically like `RunGit`: `SystemResolver` calls `tokio::net::lookup_host((host, 443))`, the system resolver git's own lookup asks too, with no timeout of its own because the system resolver gives up by itself (tokio's `net` feature is already on through pubky, `cargo tree -e features -i tokio`, and is named in the CLI's `Cargo.toml`); the tests use `test_support::FakeResolver`. Public means: IPv4 outside 0/8 (0.0.0.0 included), 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, multicast 224/4 and 240/4 (255.255.255.255 included); IPv6 inside global unicast 2000::/3, which leaves out `::`, `::1`, the deprecated IPv4-compatible `::a.b.c.d`, `100::/64`, `fc00::/7`, `fe80::/10`, `fec0::/10`, `ff00::/8` and unassigned space, but outside 2001::/23 (IETF protocol assignments, Teredo 2001::/32 and benchmarking 2001:2::/48 among them; its few reachable anycast services serve no repository), 2001:db8::/32 and 3fff::/20 (documentation); and an IPv4-mapped (`::ffff:0:0/96`), NAT64 (`64:ff9b::/96`, what DNS64 answers for an IPv4-only host such as github.com) or 6to4 (`2002::/16`) address is exactly as public as the IPv4 address it carries. Limits: git resolves the name again when it connects, so DNS rebinding between the check and git's own lookup is not closed; `http.followRedirects=false` in the git runner stops a redirect to an internal host; and with `HTTPS_PROXY` set git asks the proxy to connect, so the check is of this machine's resolver, not the proxy's.
- The target sources, P2b's record (`targets/mod.rs`, `rev.rs`, `real.rs`, `fixture.rs`). `post` and `run` reach a repository only through `TargetResolver`, a trait of async fns used generically like `RunGit`: `resolve_rev` pins a revision to a full SHA, `pull_request` gives a pull request's base, head and merge base, `fetch_remote` names the remote `run` fetches from (a `TargetRemote`, an owned `HttpsRemote` or `LocalRemote`), `check_policy` applies the target policy with no network, and `protocols` and `git_runner` give the one `GitRunner` per command, allowed that source's transports and no others, which the git-running methods take back as `&impl RunGit`. A trait with async fns cannot be `dyn`, so `Context::targets` is a `TargetSource` enum (`Real`, `Fixture(FixtureTargets)`) that passes each call on with a `match`; `main.rs` only ever builds `TargetSource::Real`. `FixtureTargets` is public so that `tests/end_to_end.rs` can build it, and `#[doc(hidden)]`, with a doc comment saying it enables git's `file` transport; it maps a `RepoName` to a plain absolute path, so no URL encoding is needed, serves only the names it maps, and allows a pull request on any of them, so the fixture's `example.invalid` pull request works. `test_support::test_context` gives a fixture source that maps nothing. The policy that a `pr` target is `github.com/<owner>/<name>` lives in the source: the real source enforces it in `check_policy`, `pull_request` and `fetch_remote`. A revision is a `RevSpec`: git's `check-ref-format` rules with one level allowed (no `..`, `@{`, lone `@`, `~ ^ : ? * [ \`, empty part, leading or trailing `/`, part that starts with `.` or ends with `.lock`, or trailing `.`), plus at most 255 bytes, printable ASCII only (so no space and no control character; a branch with a non-ASCII name is given by its SHA), no leading `-`, and no abbreviated or upper-case SHA (four or more hex digits that are not a full lower-case 40-character SHA-1; a branch with such a name is given as `refs/heads/<name>`). Its errors name the rule, never the value. Pinning is one anonymous `ls-remote`: for a short name N the patterns `refs/heads/N refs/tags/N refs/tags/N^{}` (git 2.50.1 prints the peeled line only when `^{}` is a pattern), for `HEAD` `HEAD`, for a full ref name that name and its `^{}`. The pure `match_rev` compares whole names in Rust, since git matches a pattern against a ref's tail; it resolves a tag to its `^{}` line or, for a lightweight tag, to its own SHA, refuses a name that is both a branch and a tag with a message that asks for `refs/heads/…` or `refs/tags/…`, and refuses a listing that names one ref twice. A full SHA is accepted as given once `ls-remote <url> HEAD` succeeds, which proves the repository is readable. Any `ls-remote` that exits with a failure status is the one fixed refusal "the repository is not anonymously readable (Sweepky sweeps public repositories only)": git's `GitFailed`, and the standard error it keeps, is dropped, not wrapped. A timeout, a cap or a malformed listing keeps its own fixed text. The real source checks the host (`HttpsRemote::for_repo`) before any git run, on the pin path and on the fetch path alike, and asks for `AllowedProtocols::Https` alone; its pull request half reads GitHub's unauthenticated API (next note). The fixture source asks for `HttpsAndFile`; its pull request `<n>` is `refs/pull/<n>/head`, its base the commit `HEAD` names, and its merge base `git merge-base <base> <head>`, run read-only through the runner in the bare repository (`LocalSubcommand::MergeBase`). `test_support::RecordingGit` is a `RunGit` fake that records each run's argv (`git_argv`, with the protocols it was made with) and answers with a scripted exit status and output. Limits: `ls-remote` cannot show that a commit deep in history is served, so a full SHA the repository does not have passes `post`, and `run` aborts when its fetch by SHA fails; `ls-remote` does not say what a tag points at, so a tag of a tree or a blob pins that object, and `run` fails on it; and a network failure inside `ls-remote` (git's own lookup or connection) also reads as not anonymously readable, since every failure exit does.
- GitHub's API, P2b's record (`targets/github.rs`, `real.rs`). A `pr` target must be exactly `github.com/<owner>/<name>`: another host, a third path segment or a name ending in `.git` in any case (GitHub serves `r.git` as `r`, but `run` would fetch another URL) is refused in fixed text that quotes nothing, with no network, in `check_policy`, `pull_request` and `fetch_remote`. `RepoName` already holds each segment to `A-Z a-z 0-9 . _ -`, so the two go into the API's URL path as they are. `TargetResolver::pull_request` takes a `github: &impl GitHubApi`, a trait of one async fn, `get(url, cap)`, which gives a 2xx answer's body or `None` for a 404; the caller passes the SDK's HTTP client, `ctx.network.pubky().client()` (`impl GitHubApi for PubkyHttpClient`, a plain reqwest client with the user agent `pubky.org@0.16.2` for an ICANN host), the tests `test_support::FakeGitHub`, and the fixture source never asks it anything. The real source's `pull_request` runs: the policy; `api.github.com` through the host policy (`check_host`) before the first request; `GET https://api.github.com/repos/<owner>/<name>/pulls/<n>` for `base.sha` and `head.sha`; the repository's host check and one anonymous ls-remote of the base repository's own `refs/pull/<n>/head`, which must list exactly that head, or the pull request is refused with "the pull request moved while it was being pinned; try again" (and with its own fixed text when the ref is not listed); then `GET …/compare/<base>...<head>?per_page=1&page=2` for `merge_base_commit.sha`. The head is the base repository's pull request's `head.sha`, and nothing is read from the fork. Each request is anonymous, carries `Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28`, goes through the redirect guard (next note) and is read under a 1 MiB cap. Page 2 at 1 commit a page leaves out the up to 300 changed files and their patches that page 1 carries and still carries `merge_base_commit`, checked against the live read-only API on 2026-10-19 (a one-commit pull request's page 2 has no commits and the same merge base), so the 16 MiB cap page 1 would need is not used. A status is mapped from the status alone, so an error answer's body is never read: 404 is "not found, or not public" (GitHub answers a private repository as a missing one), 403 and 429 say that for an anonymous request this almost always means the rate limit (60 requests an hour from one address) is used up, and to try again later, and any other non-2xx is "GitHub's API answered <status>". The parsers read only the fields they need into `#[derive(Deserialize)]` structs and skip the rest (an answer is read, never rewritten, so nothing is kept with `#[serde(flatten)]`), refuse a body over 1 MiB before parsing it, drop serde's error, whose text can quote the body, and hold every SHA to a full lower-case SHA-1 (`rev::is_full_sha1`). Limit: like every request through the SDK's client, whose builder sets no timeout, a GitHub request has none, so an answer that stalls waits until the command is interrupted.
- Redirects, P2b's record (`remote.rs`), the decision P2a left open: a request Sweepky sends itself refuses an answer that came through a redirect, and uses nothing of it. Those requests are each listing page (`fetch_page`), each public record read (`get_public`, moved from `public_storage().get` onto `request_async` of the resource's transport URL, the request the SDK's public storage sends, as `list_dir`'s already was) and GitHub's two reads, and all go through `get_unredirected`: `request_async`, the request's headers, `build_split` to keep the URL of the request the SDK built (it may have put an ICANN domain in place of a key, or rewritten a legacy homeserver's path), `execute`, and then the pure `check_not_redirected`, which compares the answer's URL with that one by scheme, host, port (`port_or_known_default`), path and query and refuses any difference in fixed text that names neither URL. Only then is the status looked at, by a callback given the status alone (so a redirected 404 is not an empty directory), and the body read under its cap. `BodyTooLarge` now says "the server's answer", since a body can be GitHub's. Limits, both out of scope here: pubky 0.16.2's client sets no `redirect::Policy`, so reqwest still follows up to 10 redirects and sends each redirected request, possibly to a host on the sweeper's network, and the guard refuses only the answer; and the requests the SDK sends on its own (sign-up, sign-in, sign-out and a session's reads and writes, `get_own` among them) still follow redirects. reqwest reports only the last URL, so a chain of redirects that comes back to the URL sent is not seen either.
- Under `--identity` each command signs in afresh ([03](../03-cli-and-skill.md#two-ways-to-log-in), "Session per command"), so the two concurrent `submit`s hold separate sessions. This check shows only that the lock lets both finish; the lock unit test in [P2a](P2a-cli-identity.md) shows that it serialises them. The case the lock exists for, two commands sharing one bearer, needs a restored Ring token, so [P2d](P2d-cli-ring-login.md#done-when) checks it. That is why this check rewords the former P2 item "Two `submit`s run concurrently under one grant both succeed (the lock serialises them)".
