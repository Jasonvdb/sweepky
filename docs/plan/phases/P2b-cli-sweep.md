# P2b — `sweepky-cli`: post, run and submit

## Goal

`post` for closed bounties, `run` and `submit`, so a circle member can sweep a closed bounty end to end on the testnet. It builds on [P2a](P2a-cli-identity.md) for the network config, the `--identity` login, the circle, the writers' lock, the config directories, the minimal `init` with its marker, and the testnet test; on [P1a](P1a-core-records.md) for targets, the Cloudflare converter and the bare fixture repo; and on [P1b](P1b-core-crypto.md) for the package envelope, padding and encryption. `post --open`, `pull` and `done` follow in [P2c](P2c-cli-pull-done.md).

## Build

- **`post` (without `--open`):** pins SHAs through a `TargetResolver` trait: the real one runs `git -c credential.helper= -c core.askPass= ls-remote` with `GIT_TERMINAL_PROMPT=0` (peeling annotated tags, storing full SHAs) and GitHub's unauthenticated REST API for PR head, base and merge base; the fixture one serves a bare repo under `fixtures/`. Refuses repos that are not anonymously readable. `title` and `brief` are shown for confirmation.
- **`run [<bounty-url>] [--target <tid>]`:** must be run inside an `init` project; picks or checks the bounty (circle or `open`); writes `running`; fetches each target into `./sweeps/<id>/target/<tid>/` by exact SHA (https only, depth 2, no submodules, no LFS, credential helpers disabled; PR heads from the base repo's `refs/pull/<n>/head`); removes `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.claude/` and `.mcp.json` from the copy and lists them in `scope.json`; writes `scope.json`, the brief and `.sweepky/sweep.json` (sweep URL, bounty URL, target ids, playbook id from `init`); aborts if the SHA is not served.
- **`submit [--run-dir] [--playbook]`:** canonicalise; require a direct child of `<init dir>/sweeps/` with the marker; walk with `symlink_metadata`, accept regular files with one link only, skip `agents/*/scratch/` and `target/`, cap per-file and total size, print the list; detect Cloudflare output in `audit/` and convert; read the bounty, list the owner's unrevoked `keys/`, compare with the pinned set and warn on new keys (ask, or fail with `--no-input`); refuse an owner with no keys; pad, encrypt to those plus this install's key, upload `.age`, flip to `done` (or `aborted` on failure), handling 413, 429 and 507 with clear messages.

## Done when

- The testnet test from [P2a](P2a-cli-identity.md) continues, with targets from the fixture repo: A, the owner, creates a circle with B in it and posts a closed bounty; B, a circle member, runs it inside a minimal `init` project and submits a Cloudflare-format sweep.
- `submit` refuses a run directory holding a planted symlink and a hard link to `~/.config/sweepky/*`, as in [06](../06-verification-and-limits.md#verification).
- B's first `submit` pins A's key set, and a key the test then adds under A's `keys/` makes B's next `submit` warn.
- Two `submit`s by B, of two separate runs, run concurrently and both succeed, each taking the writers' lock in turn.
- `cargo clippy -- -D warnings`, `cargo deny check` and `cargo nextest run` clean.

## Notes

- The per-sweep marker `sweeps/<id>/.sweepky/sweep.json` that `run` writes is separate from the project's `.sweepky` marker that the minimal `init` writes.
- Until [P3](P3-skill-and-sandbox.md)'s `init` records a playbook, the playbook comes from `submit --playbook`.
- `RepoName` ([P1a](P1a-core-records.md)) now refuses a host whose last label starts with a digit, not only one that is all digits: a URL parser or the system resolver reads the hex and mixed IPv4 forms (`127.0x1`, `0x7f.0x0.0x0.0x1`, `10.0.0.0xa`) as an address, every such form ends in a label that starts with a digit, and no top-level domain does. It is still a check of form: a DNS name that resolves to a private address passes it.
- The question plumbing, P2b's record (`prompt.rs`, `clock.rs`). `Context` gains `cwd`, the working directory, which `main.rs` reads with `std::env::current_dir()` so that only `main.rs` reads the environment, the working directory included (a working directory that has gone fails every command but `init` before anything is done); and `stdin`, a `StdinReader` around a `Mutex<Box<dyn BufRead + Send>>`, which `main.rs` builds around `BufReader::new(std::io::stdin())`, because `Stdin` is not `BufRead` and `StdinLock` is not `Send`, and the tests around a `Cursor`. The global `--no-input` stays on `Cli` and is not in the context: `run` hands it, as a `prompt::Prompting` (`Allowed` or `Forbidden`), to each command that asks, so a test gives it on the command line like any other flag. `prompt::confirm(ctx, prompting, question)` writes `<question> [y/N] ` to `ctx.stderr` with no newline and reads one line from `ctx.stdin` with `take(1025).read_until(b'\n', …)`, never an unbounded `read_line`: a line of more than `MAX_ANSWER_BYTES` (1 KiB, its ending included) is an error that quotes none of it, and nothing past its 1025th byte is read. `y` or `yes` in any ASCII case, once one `\n` or `\r\n` is taken off, is yes; anything else, an empty line and the end of the input included, is no. Under `Forbidden` it fails at once, with an error that names `--no-input` and the question, and writes and reads nothing. The caller sanitises any stranger's text it puts in a question. `clock::new_record_id()` is the id of a new bounty, sweep or device key: it asks `clock::now()` first, which refuses a clock before 1970 that `Timestamp::now()` would panic on, then returns `RecordId::from_timestamp(Timestamp::now())`; `device::new_device_id` is that id parsed as a `DeviceId`. Until `post` and `submit` call `confirm`, `prompt.rs` carries `#![cfg_attr(not(test), expect(dead_code, …))]`; the first caller removes it, because an unmet `expect` is a warning of its own.
- The git runner, P2b's record (`git.rs`). `post` and `run` run git only through `GitRunner`, behind a small `RunGit` trait of one `async fn run(&GitCommand) -> stdout`, used generically like `device::PublicKeys` so a test can record or fake invocations. Arguments go as an argv vector, never through a shell: options are `&'static str`s the code writes, and `git_argv` refuses an operand (URL, SHA, ref or pattern) that is empty or starts with `-`. Every run gets, before its subcommand, `-c credential.helper=` (an empty value resets the helper list, Apple git's bundled `osxkeychain` included), `core.askPass=`, `protocol.allow=never`, `protocol.https.allow=always`, `http.followRedirects=false`, `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `core.symlinks=false`, `submodule.recurse=false`, `fetch.recurseSubmodules=false`, `transfer.fsckObjects=true` and `advice.detachedHead=false`; `protocol.file.allow=always` is added only for the fixture source (`AllowedProtocols::HttpsAndFile`). The child's environment is cleared, then given exactly `PATH`, whichever of `HTTPS_PROXY`, `https_proxy`, `ALL_PROXY`, `all_proxy`, `NO_PROXY`, `no_proxy`, `SSL_CERT_FILE` and `SSL_CERT_DIR` were set (`main.rs` captures them into `Context::git_env`, a `GitEnv`, and does not read `TMPDIR`), `HOME`, `GIT_CEILING_DIRECTORIES`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_LFS_SKIP_SMUDGE=1` and `LC_ALL=C`; standard input is `/dev/null`. `HOME` is `<data dir>/git-home-<new record id>/`, made 0700 through `private_fs` and refused if anything, a symlink included, is already there; a drop guard removes it with `remove_dir_all` (best effort; a process killed outright leaves it behind). `GIT_CEILING_DIRECTORIES` is the data directory: git runs in that private `HOME` by default, and without it git's search for a repository walks up from there, so a home directory kept in git (`~/.git`) would lend its `.git/config` (an `http.extraHeader`, a `url.<base>.insteadOf`) to every `ls-remote`; a data directory whose path holds a `:` is refused, because that list is `:`-separated. That variable is the one addition to the allowlist the task named; a command run in another directory (`GitCommand::in_dir`) must run in a repository it made, so the search stops there. Each run is bounded: standard output and standard error are read at the same time, each up to its own cap, under a timeout, and a child past any of them is killed and waited for (`kill_on_drop` as well). `ls-remote` gets 60 s, 1024 lines of at most 1024 bytes (so 1,049,600 bytes of standard output) and 64 KiB of standard error; `run`'s fetch gets 10 minutes. Killing git does not kill a helper it started (`git-remote-https`), which dies when its pipes close. A failed run is a `GitFailed` error: `git <subcommand> failed with exit status <n>`, fixed text, never git's standard error, which carries `remote:` text a server wrote; the error keeps that text only for `stderr_mentions`, a match against a fixed phrase, and its `Debug` prints its length. The `ls-remote` parser takes `<40 lower-hex>\t<ref>` lines (`HEAD` or under `refs/`, no control character, `^{}` lines included): SHA-1 only, so a SHA-256 repository is refused although core's `GitSha` also takes 64 hex characters. Minimum git: 2.32, for `GIT_CONFIG_GLOBAL` (an older git still finds no `~/.gitconfig` in the empty `HOME`). tokio's `process` and `io-util` features are named in the CLI's `Cargo.toml`; pubky already turns them on (it asks for tokio's `full` on every target but wasm), so they add no code.
- Under `--identity` each command signs in afresh ([03](../03-cli-and-skill.md#two-ways-to-log-in), "Session per command"), so the two concurrent `submit`s hold separate sessions. This check shows only that the lock lets both finish; the lock unit test in [P2a](P2a-cli-identity.md) shows that it serialises them. The case the lock exists for, two commands sharing one bearer, needs a restored Ring token, so [P2d](P2d-cli-ring-login.md#done-when) checks it. That is why this check rewords the former P2 item "Two `submit`s run concurrently under one grant both succeed (the lock serialises them)".
