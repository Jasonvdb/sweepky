# P2 — `sweepky-cli`

## Goal

The `sweepky` binary, end to end against a local testnet, including open-bounty discovery and credits.

## Build

- **Network config and entry point.** A library function runs every command given a `Pubky` client, the auth relay URL and the default homeserver; the binary builds those from `--testnet` / `SWEEPKY_TESTNET=1` (testnet client, `http://localhost:15412/inbox`, the testnet homeserver) or the production defaults. The end-to-end test injects an `EphemeralTestnet`'s client instead. The watch list defaults to the selected homeserver.
- **`login` (option A, default):** `PubkyGrantAuthFlow::builder(caps, signin, "sweepky-cli").relay(cfg.relay).client(...)`, never the convenience constructor; capabilities exactly `/pub/sweepky/:rw` with the trailing slash; default grant format, no encryption scopes. A one-page loopback site (random port and path, one flow, timeout) with the QR, a copy-link button and live status, opened in the default browser; the same URL and a terminal QR as fallback. The page is a static HTML string with the QR rendered server-side as SVG by `qrcode`, no JS framework. After approval: check the granted capabilities include write on `/pub/sweepky/`, else sign out with a clear message; store the SDK's exported grant token in a 0600 file; show the expiry (two years) and warn within 30 days of it on later runs.
- **`login --identity <name> [--homeserver <pk>] [--signup-token <code>]` (option B):** local keypair under that name (created or reused), `PubkySigner::signup` then `signin_blocking` on first login, secret in a Sweepky 0600 file, optional scrypt passphrase wrap. Homeserver defaults to the testnet's under `--testnet`, else `homeserver.pubky.app`. On production, warn that this creates a separate public pubky and spends a signup token. Later commands sign in and sign out per run.
- **Shared tail of `login`:** age key generated; `keys/<deviceId>.json` written as the capability probe, mapping 403 ("this identity's signup token does not allow `/pub/sweepky/`; use a dedicated identity") and 507 ("storage quota full") to messages and aborting; device id recorded in the local list of this owner's installs; backup reminder printed. Recovery files (fixed first line) and anything shaped like a raw key or mnemonic are rejected with a one-line reason.
- **Writers' lock.** `post`, `run`, `submit`, `done`, `circle`, `keys` and `logout` take an exclusive `fd-lock` on `~/.config/sweepky/credential.lock` around session restore plus writes, because each restore replaces the grant's bearer. `pull` reads public data without a session except for its one `discovered.json` write, which also takes the lock.
- **`logout`:** mark the device key revoked, then `signout()` (which revokes the grant) or forget the identity, then delete the local files.
- **`circle create|add|remove|show`; `keys list|revoke`.** `keys list` and `pull` compare `keys/` against the local install list and alarm on unknown ids.
- **`post [--open]`:** pins SHAs through a `TargetResolver` trait: the real one runs `git -c credential.helper= -c core.askPass= ls-remote` with `GIT_TERMINAL_PROMPT=0` (peeling annotated tags, storing full SHAs) and GitHub's unauthenticated REST API for PR head, base and merge base; the fixture one serves a bare repo under `fixtures/`. Refuses repos that are not anonymously readable. `title` and `brief` are shown for confirmation. For `--open`, finds the starting cursor on the owner's homeserver (non-live event stream, `reverse`, `limit 1` after the bounty PUT) and on every other watched homeserver (exponential then binary search with `limit=1`), and writes `bounties/<id>.discovered.json`.
- **`run [<bounty-url>] [--target <tid>]`:** must be run inside an `init` project; picks or checks the bounty (circle or `open`); writes `running`; fetches each target into `./sweeps/<id>/target/<tid>/` by exact SHA (https only, depth 2, no submodules, no LFS, credential helpers disabled; PR heads from the base repo's `refs/pull/<n>/head`); removes `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.claude/` and `.mcp.json` from the copy and lists them in `scope.json`; writes `scope.json`, the brief and `.sweepky/sweep.json` (sweep URL, bounty URL, target ids, playbook id from `init`); aborts if the SHA is not served.
- **`submit [--run-dir] [--playbook]`:** canonicalise; require a direct child of `<init dir>/sweeps/` with the marker; walk with `symlink_metadata`, accept regular files with one link only, skip `agents/*/scratch/` and `target/`, cap per-file and total size, print the list; detect Cloudflare output in `audit/` and convert; read the bounty, list the owner's unrevoked `keys/`, compare with the pinned set and warn on new keys (ask, or fail with `--no-input`); refuse an owner with no keys; pad, encrypt to those plus this install's key, upload `.age`, flip to `done` (or `aborted` on failure), handling 413, 429 and 507 with clear messages.
- **`pull`:** roster polling with reverse paged listings, 404 as empty, conditional re-GETs of open bounties and `running` sweeps, cached homeserver resolution; the `/events/` watcher over the watch list through the SDK's HTTP client, 1000 per page, URI dedupe, DEL handling, re-fetch through pkarr-resolved storage, cursor advanced after each batch and persisted; trust labels from roster plus credits; unknown-key alarm; decrypt to `~/.local/share/sweepky/<bounty>/`; group findings by location keeping `reportedBy`; untrusted content into `untrusted/`; append accepted strangers' sweeps to `bounties/<id>.discovered.json`.
- **`done <bounty> [--credit] [--no-credit]`:** proposes credits from the groups, never including the owner (`--credit <own pubky>` is refused with a one-line reason), confirms interactively unless flags settle it, rewrites the bounty with `status: "done"`, `doneAt`, `credits`, preserving unknown fields. Last writer wins, deliberately.
- Config and state under `~/.config/sweepky/` (secrets, install list, pinned owner keys, 0600) and `~/.local/share/sweepky/` (pulled sweeps, groups, cursors); `SWEEPKY_HOME` overrides both.

## Done when

- The end-to-end test in [06](../06-verification-and-limits.md#verification) passes: `#[tokio::test]` + `#[pubky_testnet::test]` over an `EphemeralTestnet` with the HTTP relay, the client injected, targets from the fixture repo, identities A (owner), B (circle sweeper), C (stranger); the open bounty with its `discovered.json`; B and C running `run <bounty>` and `submit`; the planted symlink and hard link refused; C found through `/events/`, labelled `unknown`, attributed but kept in `untrusted/`, and appended to `discovered.json`; the shared location grouped with `reportedBy` {B, C} and the shared-id pair kept apart; the injected unknown key making `pull` alarm and `submit` warn; `done --credit <A>` refused; `done` proposing {B, C}; C at `known: 1` afterwards; Cloudflare-format and common-format sweeps both grouping; the later device key unable to decrypt; the second install of A decrypting the third sweep; `logout` leaving the saved token unable to restore (401); the cursor surviving a restart.
- Both login options covered in the same test, as in [06](../06-verification-and-limits.md#verification): loopback page fetched, relay host asserted local, in-process approval, status flip, a narrowed approval refused, `--identity` for B and C, a recovery file rejected, wrong loopback path 404.
- Two `submit`s run concurrently under one grant both succeed (the lock serialises them).
- Clippy, deny, nextest clean.

## Resolved questions

- **Starting cursor.** `/events/` has no "latest" shortcut: `reverse` is parsed and ignored, a timestamp cursor must match a row exactly, `limit` caps at 1000, and there is no max-id endpoint, so paging from zero on production is not viable. Resolution above: the owner's own event stream gives the event id of the bounty PUT; other homeservers are binary-searched once with `limit=1`.
- **Client id.** The SDK validates only non-empty and up to 253 characters; Ring shows it as the app name on the approval screen and in its grant list. It is `sweepky-cli`, and it never changes between releases because saved sessions are compared against it. The board uses a different id in E4 so the two grants are distinguishable in Ring.
- **Signup token for option B on production.** Plain text, three ways to get one ([06](../06-verification-and-limits.md#production-homeserver-as-deployed-on-2026-10-15)). v1 is bring-a-token.

## Notes

- `anyhow` in the binary; typed errors stay in core.
- A unit test pins the requested capability string to exactly `/pub/sweepky/:rw`; without the trailing slash it would be a file scope.
- `done` is the only command that rewrites an existing bounty record; test that a bounty posted by a newer client with extra fields survives it intact. `pull` rewrites only `discovered.json`.
- Never call the deprecated cookie sign-in; add a clippy `disallowed-methods` entry for it.
