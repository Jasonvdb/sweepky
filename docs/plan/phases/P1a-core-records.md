# P1a — `sweepky-core`: records and parsing

## Goal

The data half of `sweepky-core`: records, paths, ids, targets, the Cloudflare converter, trust labels, and the events-feed parser. Everything here is tested without a network. No I/O in this crate. Encryption, the package envelope and finding groups follow in [P1b](P1b-core-crypto.md).

## Build

- **Records:** `Circle`, `DeviceKey`, `Bounty { focus, brief, playbook, open, reward, status, credits, doneAt }`, `Discovered { sweeps, cursors }`, `Target { kind }`, `Sweep { targets[], playbook }`, `Manifest`, and the common `Findings` format with nullable `severity` and `confidence`. Every record has `schemaVersion`; open-string enums with `as_known()`; `#[serde(flatten)] extra` to preserve unknown fields. A `Bounty::mark_done(owner, credits, done_at)` that produces the rewritten record and returns an error if `credits` contains `owner`; the caller passes `done_at`, because this crate reads no clock and 01 leaves the timestamp encoding open. `status`, `credits` and `doneAt` are private, so `mark_done` (or `Bounty::new`, which credits nobody) is how this crate sets them. A `playbook` string validator for the pattern in [01](../01-records-and-discovery.md#records-v1).
- **Ids and pubkys:** 13-character Crockford timestamps via `pubky-timestamp`, validated on parse; a `Pubky` newtype that parses both `pubky<z32>` and raw z32, validates, and compares by key bytes; builders for every path under `/pub/sweepky/`; `pubky://` URL parsing for bounty and sweep references.
- **Converters:** Cloudflare `findings.json` → common `Findings`, detected by shape: `fingerprint` → `id`, verdict → `status`, severity and confidence filled only from `confirmed` records (`informational` → `info`), locations from `trace` then `evidence` with `kind` and `scope`, the original record verbatim in `extra.cloudflare`. Round-trip test on a synthetic Cloudflare-shaped fixture that rebuilds the original exactly.
- **Targets:** types for `pr` (with `mergeBase`), `commit`, `repo`; the per-kind scope description handed to the skill (three-dot PR diff, `diff-tree --root` for commits, and `diff-tree -p <rev>^1 <rev>` with the first-parent note for merges, `paths` for repos).
- **Trust labels:** `circle` / `known { bounties, owners }` / `unknown`, computed from a roster plus the whole list of bounties and their credits. The function itself, not its caller, counts only `done` bounties from trusted owners (roster members in v1) and skips any credit that names the bounty's owner. The API returns every pubky's label with its credit tally, `{ bounties, owners }`: the number of counted bounties that credit it and of their distinct owners. Circle members get a tally too, because their label is always `circle` and only the tally shows that a self-credit added nothing. The test loads [`fixtures/trust-labels.json`](../../../fixtures/trust-labels.json) and asserts the label and the tally of every `expected` entry.
- **Feed parser:** the `/events/` plain-text format (`PUT|DEL pubky://…` lines, a `cursor:` line anywhere, an empty body meaning caught up), tolerant of malformed lines; dedupe of several events for one URI.
- **Fixtures:** a synthetic Cloudflare-shaped `findings.json` with at least one `confirmed` and one `needs_validation` record; a `discovered.json`; a tiny bare git repository for the CLI's target tests, under `fixtures/`. The roster and the credited bounties for the trust-label test come from `fixtures/trust-labels.json`, which already exists.

## Done when

- Unit tests pass for: round-trip of every record including unknown fields and unknown kinds; `mark_done` preserving unknown fields and rejecting a credit for the owner; ids and both pubky forms parsing and comparing correctly, bad ones rejected; path builders; target scope descriptions for each kind; the Cloudflare converter round-trip, with `severity` null on a `needs_validation` record; feed parsing including malformed lines, the empty body, the cursor line out of order, and duplicate URIs; the trust label and tally of every `expected` entry in `fixtures/trust-labels.json`, where the fixture bounty whose owner credited themselves adds nothing to the owner's count.
- `cargo clippy -- -D warnings` and `cargo deny check` clean.
- Public API documented with `///` and `cargo doc --no-deps` warning-free.

## Notes

- The crate must not depend on `tokio`, `reqwest` or `pubky`; it may depend on `pubky-timestamp`. The CLI owns the network.
- It also depends on `base32` =0.5.1 directly, for z-base32 in `Pubky`: the release `pubky-timestamp`'s `base32` feature already pulls in (see [03](../03-cli-and-skill.md#dependencies)). `Pubky` checks the length and alphabet [01](../01-records-and-discovery.md#compatibility-rules-every-client-follows) asks for, and the canonical form, but not that the bytes are a valid Ed25519 point, since this crate has no Ed25519 code; the CLI's SDK parse does that before it uses a key on the network.
- Every parser here reads data a stranger may have written. Malformed input returns an error or is skipped; it never panics.
- Every from-bytes parse checks the input's length before parsing: at most 1 MiB (`MAX_RECORD_BYTES`) for a public record and 16 MiB (`MAX_FINDINGS_BYTES`) for a findings document. These caps are P1a's choice; 01 sets none.
- [01](../01-records-and-discovery.md) fixes only `playbook`'s pattern, so the limits on the other identifiers are P1a's choice, and P2a's device ids and P2b's target ids stay within them: a target id is 1 to 32 and a device id 1 to 64 characters of `[A-Za-z0-9_-]`, starting with a letter or digit; a repo name is at most 256 bytes, a lower-case DNS host (two or more labels of `[a-z0-9-]`, 1 to 63 characters each, not starting or ending with `-`, the last not all digits) then `/` and one or more segments of `[A-Za-z0-9._-]` that are not `.` or `..` and do not start with `-`, with no scheme, user, port or trailing `/`; a repo path is at most 512 bytes of relative UTF-8 with no control or text-reordering characters, no backslash, no empty, `.` or `..` component (one trailing `/` allowed) and no leading `-` or `:`. A record whose identifier breaks a limit is rejected whole (a target's own fields are the exception, in the next note), and a `keys/` entry whose name is not a valid device id is skipped (P2a).
- A bounty's targets are read in two steps, so a target of an unknown kind or with a bad field never rejects the bounty. Reading the bounty checks each target's `id` (a valid target id, distinct from the bounty's other target ids, else the bounty is rejected whole) and `kind` (any string) and keeps every other field as written. `Target::known` checks a known kind's fields when the target is used: an unknown kind is skipped (`Ok(None)`), and a known kind with a field missing, of the wrong type or failing its check is skipped too (`Err`). A repo target's `paths`, when present and not `null`, is a non-empty list: leave it out (or `null`) for the whole repository, since an empty list would narrow the sweep to nothing. That rule is P1a's choice; 01 says only that `paths` is optional.
- [01](../01-records-and-discovery.md) does not say how `createdAt`, `startedAt`, `finishedAt`, `doneAt` and `revokedAt` are encoded, so `RecordTime` keeps them opaque: 1 to 64 printable ASCII characters, no whitespace. Those limits are P1a's choice, not 01's.
- A `pubky://` URL's limits are P1a's choice too: the scheme `pubky://` in lower case, a host that is a pubky in either form, then a path of at most 1024 bytes that starts with `/` and has no `?`, `#`, whitespace, control or text-reordering character. The generic URL keeps any other path as written, because the events feed carries every app's files; deciding whether a path is one of Sweepky's (`SweepkyPath`, and with it `BountyRef` and `SweepRef`) is strict: exact directory, exact extension, a valid id and nothing else.
- In the findings types (`Findings`, `Finding`, `Location`) the `#[serde(flatten)]` map of unknown fields is named `unknown`, not `extra`, because a finding has a real JSON field `extra` (01's common format). On the wire nothing changes: unknown keys sit beside the known ones at each level. Reading is lenient where 01 is silent, because agents write this format: a missing `severity` or `confidence` reads as `null` and is written as `null`, a `null` `fix` or `extra` reads as absent, and `playbook`, `file` and `scope` are unchecked strings (the checked playbook is the manifest's).
- The Cloudflare converter's reading rules are P1a's choice where [01](../01-records-and-discovery.md#the-sweep-package) is silent. An audit's `findings.json` is capped at `MAX_FINDINGS_BYTES` and detected by shape: an object is the common format, an array is Cloudflare's, and an empty array is a run that found nothing. Each array item must be an object with a non-empty string `fingerprint`, a string `verdict` (any value, kept as the open-string `status`), and a string `title` and `description`. `trace` and `evidence` may be left out; when present, each is a list of objects with a string `file`, a `line` of 1 or more if given and, in `trace` only, a string `kind` and `scope` if given. A field the converter reads that has the wrong type fails the conversion with an error that names the item's index and the field, never its content. `severity` and `confidence` are read from `confirmed` records only, and a value outside Cloudflare's lists reads as `null`. `fix` is `remediation.strategy` alone: `remediation.code_changes` hold whole fixed files rather than a diff, so they stay in `extra.cloudflare` with the rest of the record.
- `Manifest` has no `schemaVersion` of its own: 01's package example puts `schemaVersion` on the package envelope around it (P1b), and the manifest is not one of 01's six record kinds.
- The events-feed parser's limits and reading rules are P1a's choice where [01](../01-records-and-discovery.md#discovery) is silent. `parse_feed` takes the body as bytes, refuses one over 4 MiB (`MAX_FEED_BODY_BYTES`) whole, and otherwise never fails. It reads `\r\n` endings as `\n` and skips empty lines without counting them. An event line is `PUT` or `DEL` in upper case, one space and a URL `PubkyUrl` accepts. A cursor line is `cursor: ` and canonical decimal, and the first valid one wins, so a later cursor line is malformed. Every other line, including one over 4096 bytes (`MAX_FEED_LINE_BYTES`) or one that is not UTF-8, is skipped and counted. A page is caught up only when it has no events, no cursor and no malformed line. `deduped()` keeps each URL's last event, comparing keys by bytes, and `sweep_records()` keeps only sweep-record URLs from that, both `PUT` and `DEL`.
