# P2a — `sweepky-cli`: identity, keys and circle

## Goal

The first part of the `sweepky` binary: the network config and library entry point, `login --identity` with the shared tail of `login`, `keys`, `logout`, the circle, the writers' lock, the config and state directories, and a minimal `init`. It builds on the records, the `Pubky` newtype and the path builders from [P1a](P1a-core-records.md), and on the age keys and secret types from [P1b](P1b-core-crypto.md). The Ring login (option A) follows in [P2d](P2d-cli-ring-login.md).

## Build

- **Network config and entry point.** A library function runs every command given a `Pubky` client, the auth relay URL and the default homeserver; the binary builds those from `--testnet` / `SWEEPKY_TESTNET=1` (testnet client, `http://localhost:15412/inbox`, the testnet homeserver) or the production defaults. The end-to-end test injects an `EphemeralTestnet`'s client instead. The watch list defaults to the selected homeserver.
- **`login --identity <name> [--homeserver <pk>] [--signup-token <code>]` (option B):** local keypair under that name (created or reused), `PubkySigner::signup` then `signin_blocking` on first login, secret in a Sweepky 0600 file, optional scrypt passphrase wrap. Homeserver defaults to the testnet's under `--testnet`, else `homeserver.pubky.app`. On production, warn that this creates a separate public pubky and spends a signup token. Later commands sign in and sign out per run.
- **Shared tail of `login`:** age key generated; `keys/<deviceId>.json` written as the capability probe, mapping 403 ("this identity's signup token does not allow `/pub/sweepky/`; use a dedicated identity") and 507 ("storage quota full") to messages and aborting; device id recorded in the local list of this owner's installs; backup reminder printed. Recovery files (fixed first line) and anything shaped like a raw key or mnemonic are rejected with a one-line reason.
- **Writers' lock.** `post`, `run`, `submit`, `done`, `circle`, `keys` and `logout` take an exclusive `fd-lock` on `~/.config/sweepky/credential.lock` around session restore plus writes, because each restore replaces the grant's bearer. `pull` reads public data without a session except for its one `discovered.json` write, which also takes the lock.
- **`logout`:** mark the device key revoked, then `signout()` (which revokes the grant) or forget the identity, then delete the local files.
- **`circle create|add|remove|show`; `keys list|revoke`.** `keys list` and `pull` compare `keys/` against the list of device ids this owner's own installs created and alarm on unknown ids.
- Config and state under `~/.config/sweepky/` (secrets, install list, pinned owner keys, 0600) and `~/.local/share/sweepky/` (pulled sweeps, groups, cursors); `SWEEPKY_HOME` overrides both.
- **`sweepky init <dir>` (minimal):** creates the directory, writes the `.sweepky` marker and a `.gitignore` containing `sweeps/`, and nothing else. `run` ([P2b](P2b-cli-sweep.md)) requires that marker. The rest of `init` belongs to [P3](P3-skill-and-sandbox.md): the sandbox `.claude/settings.json`, the project `CLAUDE.md`, the skill copy into `.claude/skills/sweepky/`, the playbook install and the launch line.

## Done when

- Unit tests pass for: the requested capability string; the lock serialising two writers; the 403 and 507 mapping to their messages; a recovery file rejected.
- A testnet test logs in a throwaway identity with `--identity`, publishes a key, lists it, revokes it and logs out; after `logout` this install's key record has `revokedAt` set, and the identity and its local files are gone. The throwaway identity is not one of A, B or C from the end-to-end test in [06](../06-verification-and-limits.md#verification). The test runs as `#[tokio::test]` + `#[pubky_testnet::test]` over an `EphemeralTestnet` with the HTTP relay, the client injected.
- `cargo clippy -- -D warnings`, `cargo deny check` and `cargo nextest run` clean.

## Resolved questions

- **Signup token for option B on production.** Plain text, three ways to get one ([06](../06-verification-and-limits.md#production-homeserver-as-deployed-on-2026-10-15)). v1 is bring-a-token.

## Notes

- `anyhow` in the binary; typed errors stay in core.
- A unit test pins the requested capability string to exactly `/pub/sweepky/:rw`; without the trailing slash it would be a file scope. The constant and its test land here, but the first code that requests the capability is [P2d](P2d-cli-ring-login.md)'s grant flow, because `--identity` signs in with the root signer.
- The testnet test is the start of the end-to-end test from [06](../06-verification-and-limits.md#verification). [P2b](P2b-cli-sweep.md) and [P2c](P2c-cli-pull-done.md) extend this same test and [P2d](P2d-cli-ring-login.md) completes it, so no phase adds a second one. P2a's own steps use the throwaway identity rather than A, B or C because `logout` deletes the identity it runs on, and B's `submit` in P2b needs A to hold an unrevoked key. No later phase uses the throwaway identity, so P2b–P2d extend the test without reordering these steps. Restoring a saved token after `logout` is checked in P2d, the first phase that saves one.
- Never call the deprecated cookie sign-in; add a clippy `disallowed-methods` entry for it.
- `sweepky-cli` is a library plus a thin binary. `main.rs` alone reads the environment (`std::env::var_os`, never clap's `env` feature) and passes the values in; it builds the `Context` around a `Network`, calls `run(cli, &ctx)`, prints the `Report`'s text as it is, and on failure prints `error: {:#}` and exits with status 1. `anyhow` is used in both halves of the crate ([03](../03-cli-and-skill.md#rust-conventions-teaching-notes-keep-in-code-comments)'s convention now reads that way); `sweepky-core` keeps its typed errors.
- Network values, P2a's record. Production: the relay is the SDK's `pubky::DEFAULT_HTTP_RELAY_INBOX` (`https://httprelay.pubky.app/inbox` at 0.16.2) and the homeserver is `8um71us3fyw6h8wbcxb5ar3rwusy1a6u49956ikzojg3gcwd1dty`, `PRODUCTION_HOMESERVER` in `src/utils/constants.ts` of `pubky/pubky-ring` at `5ad21e22dd37c11817bd6aa7026b4990b35e1f89` (`pubky/pubky-nexus` names the same key as the Synonym homeserver in `nexusd/default.config.toml` at `8641d38a1ddbb8435dfda4d892ca954eef6ba314`). Testnet: `http://localhost:15412/inbox` and `8pinxxgqs41n4aididenw5apqp1urfmzdztr8jt4abrkdn435ewo`. Every kind's watch list, the injected one's included, defaults to its default homeserver alone. The values live in `NetworkSettings`, apart from the client in `Network`, so the unit tests check every kind without building a client: a production client starts a DHT node that contacts public bootstrap servers, and no test builds one.
- `SWEEPKY_TESTNET`: exactly `1` or `true` selects the testnet, as `--testnet` does (a global flag, before or after the command); unset, `0`, `false` or empty is production. Any other value, other spellings and a value that is not UTF-8 included, is an error even with the flag, so a typo never sends a run to production.
- The client id is `sweepky-cli` (`CLIENT_ID`) and the requested capability `/pub/sweepky/:rw` (`SWEEPKY_CAPABILITY`); both constants are in `network.rs`, with the capability's unit test.
- The clippy ban lives in `crates/sweepky-cli/clippy.toml` (not at the workspace root, so `sweepky-core`, which has no `pubky` dependency, never reads paths it cannot resolve). Besides the cookie sign-in entry points (`PubkySigner::signin_cookie`, `signin_cookie_blocking`, `signup_cookie`, `Pubky::start_cookie_auth_flow`, `resume_cookie_auth_flow`) it bans the other deprecated cookie-session paths (`Pubky::session_from_file`; `PubkySession::import`, `import_secret`, `from_secret_file`, `write_secret_file`), `Keypair::write_secret_key_file` and `from_secret_key_file` (on `pubky::Keypair` and on the `pubky::pkarr::Keypair` it derefs to), which bypass Sweepky's own 0600 secret-file writer, and the recovery-file helpers (`Pubky::signer_from_recovery_file`, `recovery_file::decrypt_recovery_file` and `create_recovery_file`), because importing an identity's recovery file is refused and a dedicated identity's secret is never kept in that format. Every entry resolves at `pubky` 0.16.2, checked by hand: a temporary call to each was flagged, and clippy prints "does not refer to a reachable function" for a path that does not resolve and printed it for none of these. None was dropped.
- The `init` marker, P2a's choice: `.sweepky` holds the JSON object `{"schemaVersion":1}` and a newline, so P3 can add fields. It is written last, with `create_new` (`O_CREAT | O_EXCL`, which fails on anything at the path, a dangling symlink included), so a marker present means a finished `init`, and a second run reports the directory already initialised and changes nothing. A new `.gitignore` is created the same way holding `sweeps/`; an existing one is appended to only when no line reads exactly `sweeps/` (bytes, split on `\n`), starting a new line first if the file does not end with one, so every existing byte stays. `init` refuses a marker or `.gitignore` that is a symlink or not a regular file, and will not append to a `.gitignore` with a second hard link (that would change the other name too); before reading or appending it checks that the file it opened is the one it inspected (same device and inode).
- `cargo deny check` (a deviation from P0's `deny.toml`). With `pubky` and `pubky-testnet` in, advisories failed on two counts on 2026-10-16. RUSTSEC-2023-0089: `atomic-polyfill` is unmaintained; it comes in through pubky-common → postcard → heapless 0.7, which needs it only on avr, riscv32 `-none-elf`, thumbv6m and xtensa. RUSTSEC-2026-0194 and RUSTSEC-2026-0195: `quick-xml` 0.39.4, two denial-of-service bugs in parsing untrusted XML, dev-only through pubky-testnet → pubky-homeserver 0.16.2 → opendal-core 0.57.0 (`^0.39.3`); the fix is in quick-xml 0.41, which needs opendal-core 0.58, and pubky-homeserver's `opendal = "0.57"` excludes that. `deny.toml` now limits `[graph] targets` to `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `aarch64-apple-darwin` and `x86_64-apple-darwin`, which takes atomic-polyfill out of the graph (the alternative was an ignore entry for it), and ignores the two quick-xml advisories with reasons, to be removed when pubky-testnet moves to opendal 0.58. Licences, bans and sources are unchanged: all eight licence entries and the `option-ext` exception are in use.
- `tempfile` =3.27.0 is a new dev-dependency of `sweepky-cli`, added to [03](../03-cli-and-skill.md#dependencies)'s table: `pubky-testnet` already brings that release into the graph, so it adds no code. `fd-lock` arrives with the writers' lock.
- Record times, P2a's record (P1a left the encoding to this phase). Sweepky writes every time field, `createdAt` and `revokedAt` here and `startedAt`, `finishedAt` and `doneAt` in later phases, as RFC 3339 in UTC with `Z`, to the second: `YYYY-MM-DDTHH:MM:SSZ`, such as `2026-10-16T09:41:07Z`. `sweepky-core` builds the text with `RecordTime::from_unix_seconds(u64)`, which is pure, so core still reads no clock: Howard Hinnant's `civil_from_days` with checked arithmetic (clippy's `arithmetic_side_effects` lint is on for it), for the years 1970 to 9999, and an `Err` for any later second, because an RFC 3339 year has exactly four digits. The CLI's `clock::now()` reads `SystemTime::now()` against the Unix epoch and drops the fraction of a second; a clock before 1970 or past 9999 is an error message, never a panic. Readers stay opaque, as P1a set out: `RecordTime` never parses a date, has no ordering and accepts any valid value, so a record another client wrote with milliseconds or an offset still reads. [01](../01-records-and-discovery.md) leaves the encoding open and is unchanged.
- Config and state directories, P2a's record (`dirs.rs`). By default the config directory is `$HOME/.config/sweepky/` and the data directory `$HOME/.local/share/sweepky/`. `SWEEPKY_HOME=<dir>` moves both: config to `<dir>/config/`, data to `<dir>/share/`, and `HOME` is then not read. `XDG_CONFIG_HOME` and `XDG_DATA_HOME` are ignored, because the sandbox template denies reads of exactly `~/.config/sweepky` and `~/.local/share/sweepky` ([02](../02-encryption-and-safety.md#sweeper-safety)). The variable in use must be a non-empty absolute path: an empty or relative `SWEEPKY_HOME` is an error, never a fall back to `HOME`, so a script that meant to keep an identity apart never writes into the user's own config, and a missing, empty or relative `HOME` without `SWEEPKY_HOME` is an error too. `main.rs` reads both variables with `var_os` and passes them to `Dirs::resolve`, which touches no file, and the `Context` carries the result. The config layout: `credential.lock` (the writers' lock), `login.json` (which login this install uses), `installs.json` (the device ids this owner's installs created), `device.key` (this install's age identity), and `identities/<name>.key` and `identities/<name>.json` (a dedicated identity's secret and its public details). The pinned owner keys ([P2b](P2b-cli-sweep.md)) and the data directory's subtrees ([P2c](P2c-cli-pull-done.md)) are added by those phases. A directory is created by the first command that writes into it, not at start-up.
- Identity names, P2a's choice: `--identity <name>` is an `IdentityName`, 1 to 64 characters of `[A-Za-z0-9_-]` starting with a letter or digit (the device id's rule), so `identities/<name>.key` is always one plain path segment inside `identities/`.
- Owner-only files (`private_fs.rs`), which every secret and state file goes through. Directories are created 0700 (`DirBuilder` with `mode`, parents included) and files 0600 (`OpenOptions` with `create_new` and `mode` on a temp file beside the target, named from the process id, the clock and a counter), so the mode is set by the call that creates them and never by a later `chmod`; `umask` can only take bits away. A file is written with `write_all` and `sync_all` and then renamed over the target, and the temp file is removed if any step fails. A symlink (dangling or not) or anything but a regular file is refused on read and write, and a directory that is a symlink or not a directory is refused. A directory with any group or other permission bit, and a file being read with one, is refused, not fixed, with the `chmod 700` or `chmod 600` that fixes it, as ssh refuses a loose key; a write replaces whatever regular file is at the target, loose or not, with a new 0600 one, because the rename swaps the whole file and no `chmod` is involved. Ownership is not checked separately, because another user's 0600 file or 0700 directory cannot be opened anyway. A read checks type, mode and size against the caller's cap on the `lstat` before opening, checks after opening that it got the same file (device and inode, as `init` does) and repeats the checks on it, then reads exactly that many bytes with `read_exact` into a zeroed `Zeroizing` buffer that never grows, and refuses a file that grew or shrank meanwhile. A missing file reads as `None`. Removing a missing file counts as success, so `logout` can tidy up a partly missing state; the bytes are not overwritten first, which on SSDs and copy-on-write filesystems would promise more than it does.
- Writers' lock, P2a's record (`lock.rs`). `WritersLock::open(&Dirs)` creates the config directory (0700) if needed and opens `credential.lock` through `private_fs::open_private_lock_file`: read and write, created empty and 0600 with `create_new`, never truncated or replaced, and a symlink, anything but a regular file or a loose mode refused as for every other config file, with the same device-and-inode check after the open. `hold(on_wait, work)` tries `fd_lock::RwLock::try_write` (`flock` with `LOCK_NB`); on `WouldBlock` it calls `on_wait` once, for the caller's "waiting for another sweepky command" line, and tries again after a `tokio` sleep of 10 ms doubling to 500 ms, giving up after 10 minutes with an error naming the file. The blocking `write()` is never called: in-process tests run several commands on one runtime, where it would deadlock. `work` is an async closure run while the lock is held, and the lock is released when it returns, fails or is dropped. It is not a guard-returning `acquire`, because a retry loop that returns `fd-lock`'s guard, which borrows the lock, does not compile under today's borrow checker (`E0499`). A `flock` belongs to an open file, so two `WritersLock`s in one process exclude each other as two processes do, and the kernel drops it when the process exits, so no lock is ever left behind. Nothing deletes or replaces `credential.lock`, `logout` included, because a new file would let a second writer in. The unit tests: two writers on a multi-thread runtime never overlap; a second writer waits while the first holds the lock, and says so once (on a single-thread runtime with a 30-second limit, so a blocking wait fails the test rather than hanging it); the give-up; the file's mode and the symlink refusal. `fd-lock` =4.0.4 adds only itself to `Cargo.lock` (`cfg-if`, `rustix` 1.1.5 and `windows-sys` 0.52.0 were already there), and the tests turn on tokio's `sync` feature for a oneshot channel and a barrier.
- Remote reads and write errors, P2a's record (`remote.rs`). `get_public(pubky, owner, path, cap)` reads anyone's public file through the SDK's public storage, addressed with the `(PublicKey, path)` pair rather than a formatted URL; `get_own(session, path, cap)` reads the signed-in user's own. Both give `None` for a 404 and hand back the body in a `Zeroizing` buffer. Every body goes through `read_capped`: a `Content-Length` over the cap is refused before a byte is read, then the body is read chunk by chunk and refused at the chunk that would cross the cap, which is never copied in; growing the buffer moves it into a new one so the old one is wiped. A record is read with `MAX_RECORD_BYTES` and parsed with its type's capped `from_json`, the only record parser; the SDK's `text()`, `bytes()`, `get_json` and `list().send()` are never used on remote data. `read_capped` takes the response's `content_length()` and an `async || response.chunk().await` closure rather than the response, because the response is `reqwest`'s type and the crate has no `reqwest` dependency to name it with.
- Directory listings, P2a's record. The SDK's `ListBuilder::send()` is not used: in pubky 0.16.2 (`actors/storage/list.rs`) it buffers the whole answer with `resp.bytes()` and decodes it with `String::from_utf8_lossy`, and `.limit()` bounds only what an honest server sends. `list_dir(pubky, owner, dir, limits)` sends its own anonymous `GET` (`pubky.client().request_async(Method::GET, url)`, the path the SDK's public storage uses) to the directory's `PubkyResource::to_transport_url()` with `limit=<page size>` and, after the first page, `cursor=` the last entry's `pubky://` URL. It checks the status itself: a 404 is an empty directory (the homeserver answers 404 "Directory Not Found" for one with nothing in it, confirmed on an `EphemeralTestnet` on 2026-10-16), any other non-2xx an error naming the status alone, whose body is never read. Each page is read through `read_capped` with a cap of page size × (4096 + 2) bytes and parsed by `ListingParser`: lines split at `\n` with one `\r` dropped and trimmed, blank lines ignored; a line over 4096 bytes, not UTF-8 (never decoded lossily) or not a `pubky://` or `https://` resource URL refuses the listing, and so do a page with more entries than asked for and a listing past `max_entries` or `max_pages`. An entry of another owner (compared as keys, by bytes) or outside the directory is skipped and counted, and so is one `SweepkyPath::parse` refuses, such as a `keys/` name that is not a valid device id. A page with fewer entries than asked for is the last; a full page continues from its last entry of this owner inside the directory, and a full page with none is refused. `ListLimits::DEFAULT` is 100 entries a page, at most 1000 entries in 11 pages. A page size outside 1 to 1000 is refused before any request, because the homeserver quietly sends at most 1000 whatever `limit=` asks for, and a capped page would read as a short last page and cut the listing off. `url` =2.5.8 becomes a direct dependency for the `Url` these take ([03](../03-cli-and-skill.md#dependencies)).
- Write errors, P2a's record. `write_refusal` maps a 403 to "the homeserver refused the write (HTTP 403): this identity's signup token does not allow `/pub/sweepky/`; use a dedicated identity" and a 507 to "the homeserver refused the write (HTTP 507): storage quota full; use a dedicated identity", for `login`'s key write to abort with; every other error goes through `request_error`. Neither quotes the server's error body or a request URL: a homeserver's answer is shown as its status and the `http` crate's reason for it, a transport error as "network error" with "timed out" or "could not connect" and any status, and the rest as fixed sentences. The SDK's own `Display` of a transport error includes the URL, and its server error carries the server's text, so neither is ever printed.
- Terminal sanitiser, P2a's record (`display.rs`), for P1a's carry-forward note to P2c, applied here to key labels and circle names and labels. `sanitize(text, max_chars)` writes as visible `\u{..}` escapes every control character (C0, DEL, C1, so ESC and every escape sequence it starts), the separators U+2028 and U+2029, every Unicode 16.0 format character (`Cf`: the bidi controls U+061C, U+200E/F, U+202A–202E and U+2066–2069, the zero-width characters, U+FEFF, U+00AD, the tag block and the rest), every other default-ignorable code point and the noncharacters; it doubles a backslash so no stranger can write a lookalike escape; and it shows at most `max_chars` characters of the text (`MAX_LABEL_CHARS`, 64, for labels and names), counted as characters, then `…(truncated)`. Ordinary text, accents, other scripts and emoji are unchanged, except that an emoji built with U+200D or a variation selector shows those as escapes.
- For [P3](P3-skill-and-sandbox.md): the sandbox's two `denyRead` entries name the default directories only. A `SWEEPKY_HOME` elsewhere is protected by `blockReadsOutsideWorkingDirectories` alone, so it must stay outside the `init` project and any other directory the agent works in. P3's `init` should check that and say so.
