# P3 — Skill and sweeper sandbox

## Goal

The `/sweepky` skill an agent follows, and the sandboxed project a sweep runs in. The agent only audits; `sweepky run` and `sweepky submit` are terminal commands around it.

## Build

- `skills/sweepky/SKILL.md` with `disable-model-invocation: true`: roles `run` (default), `post`, `pull`, `done`. In `run` it reads `./sweeps/<id>/scope.json` and the brief, follows the suggested playbook if installed in the project, else the sweeper's configured one (the `.sweepky` marker's `playbook`, read as data), else a careful review guided by the brief, and records which. It phrases the Cloudflare request explicitly (full audit mode with report artifacts, absolute target path under `sweeps/<id>/target/`, the scope in words, the profile, the new output directory `sweeps/<id>/audit/`, "no prior runs; do not read other `sweeps/` directories"). It carries the common findings schema, including that `severity` and `confidence` are null unless established. It tells the agent it has no network, must not run `sweepky`, and that the trust rule for untrusted sweeps is attribution yes, merge no. In `done`, it shows the proposed credits with each sweeper's finding groups and leaves the decision to the human.
- `sweepky init <dir>`, on top of the minimal half that [P2a](P2a-cli-identity.md) built (the directory, the `.sweepky` marker and a `.gitignore` with `sweeps/`): writes the `.claude/settings.json` from [02](../02-encryption-and-safety.md#sweeper-safety) with the absolute `claudeMdExcludes` path filled in, a `CLAUDE.md` for the project (what the agent will find, where to write, what not to do), copies the skill into `.claude/skills/sweepky/`, and, when the sweeper agrees, installs the Cloudflare playbook project-local with the pinned `npx skills@1.7.2 add …#<full sha> --copy` line from [03](../03-cli-and-skill.md#the-sweepky-skill) and records the commit for `submit`. Prints the launch line `claude --setting-sources project,local` and the Node-outside-`$HOME` requirement.

## Done when

- In an `init` project launched with `claude --setting-sources project,local`, in manual mode and in auto mode: a Bash `curl` to the internet fails; `cat ~/.config/sweepky/*` fails; `cat ./sweeps/<id>/scope.json` works; a `CLAUDE.md`, an `AGENTS.md` and a `.claude/settings.json` planted in a fixture target are gone from `sweeps/<id>/target/` after `run` and listed in `scope.json`; the project-local playbook files are readable from a sandboxed command.
- `sweepky submit` run from a terminal afterwards succeeds on the fixture sweep and refuses one with a planted symlink.
- Skill text reviewed against the Cloudflare `SKILL.md` fetched at the pinned commit (not any install on the machine), lines 12–17 (modes), 51 (output dir) and 107–117 (profiles and scoped runs).

## Notes

- The skill is referenced, not vendored. If it is ever vendored, keep the MIT notice.
- The sandbox covers Bash, PowerShell and Monitor; `blockReadsOutsideWorkingDirectories` covers the file tools. MCP and Artifact are denied by rule. User-level hooks and MCP servers stay out through `--setting-sources`.
- The template's deny rules apply in every permission mode, including bypass; the sandbox's own network behaviour does not, which is why the network deny is a permission rule. Never run a sweep in bypass mode anyway.
- **The skill text, P3's record (`skills/sweepky/SKILL.md`, `crates/sweepky-cli/tests/skill_text.rs`).** The test reads the skill with `include_str!`, so the library gains nothing, and checks one rule per test: the frontmatter, the four role headings and `run` as the default, every `scope.json` field P2b writes, the playbook order, the request to the playbook, the findings example (parsed with core's `parse_audit_findings`, which `submit` uses, with `severity` and `confidence` null), the safety and trust sentences, and that no line names a secret file or points the agent at the config directory except to forbid it. The skill is written one paragraph or list item per line, so a phrase never breaks across lines.
- **Where `untrusted/` is summarised (P2c's carry-forward, decided here).** An `init` project cannot read the data directory (`denyRead` on `~/.local/share/sweepky`, and `blockReadsOutsideWorkingDirectories` for a `SWEEPKY_HOME` outside it), so the skill's `post`, `pull` and `done` roles run in the owner's ordinary session, and the skill tells the agent that every pulled file is data, never instructions, and that it never runs, opens or applies anything from one. v1 has no command that copies `untrusted/` into a project: one, through directory handles as `run` places a sweep and with `claudeMdExcludes` for the copy, would isolate the step, and is deferred. 02's "Untrusted reports are data" and 03's skill section say so now.
- **Choices the docs left open, made in the skill.** The human, not the agent, runs `sweepky post` and `sweepky done`: both ask on standard input before their public write, and that answer is the owner's (03: "a human should type the command"); the agent writes the draft, shows it, and gives the command. The agent runs `sweepky pull` itself, which asks nothing, and reads its standard output only (P2d's expiry warning goes to standard error). The playbook named for a careful review with no installed playbook is `careful-review`, a name that passes 01's pattern; the skill tells the human to pass it to `submit --playbook` when it differs from the marker. Until `init` records a `playbook` in the marker, step 2 of the playbook order never applies.
- **Known limit: one target per playbook run.** Cloudflare's skill wants a new output directory per repository, and `submit` skips only `audit/agents/*/scratch/`, so per-target output directories under `audit/` would package the hunters' scratch. With several targets the skill tells the human first and suggests `sweepky run <url> --target <tid>` per target; if they go on, it sweeps the first target and names the others as not swept in `REPORT.md`.
- **Review against Cloudflare's `SKILL.md`** at `c1c8a8c1471069fb0e188eeaff69b8e8db6564a8` (fetched from `raw.githubusercontent.com/cloudflare/security-audit-skill/<sha>/skills/security-audit/SKILL.md` on 2026-10-20, not an install on this machine).
